How I approached them

Each project started small. The goal was not to build something huge — it was to understand a problem, make a working version, and learn from it.

01
SMART FILE ORGANIZER

Turning a messy folder into a small automation challenge.

Problem

Downloads and study files can quickly end up mixed together, making it annoying to find things later.

Idea

Use a simple script to recognize file extensions and move files into useful categories automatically.

What I built

A Python script that checks files in a folder and sorts common formats into Images, Documents, Media, and other folders.

What I learned

Small automations can remove repetitive work, and clear logic matters more than making a first project complicated.

02
EXPENSE TRACKER

Making everyday spending easier to see.

Problem

Small daily purchases are easy to forget, so it can be difficult to understand where money is actually going.

Idea

Create a lightweight page where an expense can be added in seconds and the running total stays visible.

What I built

A browser-based tracker that accepts expenses, categories them, calculates totals, and keeps entries using local storage.

What I learned

Handling user input made me think about the experience around the code — not only whether the feature technically works.

03
INTERACTIVE TO-DO

Practicing interaction through a familiar daily tool.

Problem

A static webpage taught me structure and styling, but I wanted to understand how user actions change what appears on screen.

Idea

Use a simple task list as a practical way to experiment with adding, completing, and deleting items.

What I built

A responsive to-do page using HTML, CSS, and JavaScript with interactive task controls.

What I learned

I became more comfortable connecting interface elements to JavaScript logic and debugging unexpected behavior.
